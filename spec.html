MERIT-Record v0.1 (draft)

스코프 디스클레이머: 이 스펙과 lint는 스키마·규칙 적합성만 판정한다 —

기여의 진본성·사실성·가치·평가 공정성은 판정 대상이 아니다 (§6 참조).

백로그 #21 (A005 protocol ①·②). 2층 구조: "30분 구현" 목표는 코어에만 적용된다.

1. 파일 형식 (normative)

  • JSONL: 한 줄 = 레코드 1개. UTF-8, BOM 금지. append-only — 기존 라인 수정·삭제 금지.
  • ts는 ISO8601 + UTC 오프셋 필수 (예: 2026-07-04T10:12:23+09:00).
  • 정정·재판정은 새 라인 + supersedes 구조화 필드로만 (자유 텍스트 정정 폐지).
  • 미지 필드는 무시한다 (must-ignore) — 전방 호환.

2. 코어 필드 (contribution record, 필수 ≤8)

필드타입규칙
idstring원장 내 유일 (lint가 중복 검사 — 병렬 세션 채번 충돌 대비)
tsstringISO8601+offset
contributorstring핸들만 — 핸들 외 개인정보 금지
summarystring1줄
evidencearray링크/경로 목록 (내용물의 PII 금지)
lensesobjectnovelty/effort/impact/care 각각 {score: 0–5 정수, why|note: 1줄}
totalint= sum(lenses.score) 파생값 — 불일치는 오류. total 스칼라만의 순함수로 어떤 배분·랭킹도 만들지 않는다(리포트는 렌즈 벡터 병기)
ledger_idstring발행 원장 식별자. 원장 로컬 파일에서는 생략 가능(bare = 자기 원장 해석, §5). 원장 간 교환 시 필수

3. 확장 필드 (선택)

evaluator, model_id, supersedes, cross_ledger, type, project

  • supersedes: 대체된 레코드 id — 집계 시 원본 제외 (이중합산 방지). 참조 대상은 존재해야 한다.
  • cross_ledger: 타 원장 유래 표시 (bool 또는 원장 id) — append-only에서 구분 없이 섞이면 소급 재조정 불가하므로 문법만 지금 예약.
  • type/project: 자유 분류 (canonical type은 score-mapping 참조).
  • status_level: non-normative 파생값 — 기록될 수 있으나 규범 아님.

4. attestation record

필드규칙
id, ts, attester, contribution_id필수 (id 유일, ts ISO8601+offset)
value_received1문장 필수 (v0.1 이후 신규 레코드; 이전 레코드는 경고만)
artifact선택 — 수혜 근거 링크/경로
note선택 1줄

적립 규범 (집계기 의무): **dangling(대상 부재) 0 · 셀프(자기 기여) 0 · 동일

(attester, contribution_id) 중복 0.** 원장 내부의 유효 attestation은 무조건 +1

보존 — 조건부화는 원장 경계(cross-ledger)에서만 (A005 원칙④ 명시 결단).

5. 연합 (federation) — 문법만 예약

  • URI: merit:<ledger_id>:<local_id> / 핸들: name@ledger_id / bare id = 자기 원장 해석.
  • config의 trusted_ledgers allowlist: 미등록 원장발 attestation은 파싱되되 적립 0.
  • 크로스-원장 적립·정산 의미론은 이 버전에 존재하지 않는다 (experimental) — 독립 원장 2개의 라이브 상호운용 데이터 확보 후 v0.2에서 확정한다 (IETF "독립 구현 2개 상호운용 전 표준화 금지" 준수). 본 스펙의 어떤 문구도 원장 간 정산·지급을 규정하지 않는다.

6. 이 스펙이 보장하지 않는 것 (위협모델 요약)

  • 진본성·사실성 — 기여가 실제 있었는지, evidence가 진짜인지 검증하지 않는다.
  • 신원 — contributor/attester 핸들의 실존·동일성 (aliases는 운영 편의 병합일 뿐).
  • 변조 방지 — 암호학적 무결성 없음 (P0 금지선). 파일 소유자는 기술적으로 재작성 가능하며, 방어는 append-only 규율 + 공개 리포트 diff 관측뿐.
  • 평가 공정성 — 4렌즈 점수의 품질은 평가자(운영자 LLM) 캘리브레이션 소관 (미해결 §: 평가자 단일점).

7. 거버넌스

  • 동결된 버전은 영구 유효 — 운영자를 포함해 누구도 기존 라인을 소급 무효화할 수 없다.
  • 개정은 새 schema_version 발행으로만. 포크 자유 명시.
  • PII: redaction 라인 타입 + "컴플라이언스 재작성" 절차만이 유일하게 허용되는 파일 변형(기록 의무) — 상세 절차는 v0.2 과제.
